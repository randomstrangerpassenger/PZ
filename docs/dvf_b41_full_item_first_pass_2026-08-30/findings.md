# DVF 전체 2,105개 1차 점검 결과

현재 generation에 있는 2,105개 exact FullType 전부를 점검 대상으로 삼았다. 일부 샘플을 전체로 일반화한 결과가 아니다. 다만 이번 전수 작업은 **현재 설명·기존 추출 입력·원본 근거의 보존 정도와 다음 조사 경로를 대조한 1차 점검**이다. 모든 아이템의 모든 게임 동작과 설명 문장의 사실성을 확정한 검증은 아니다.

결론은 **`uc.action.construction` 같은 분류만으로 구체적인 활동·효과를 만들어 쓰면 안 되지만, 더 구체적인 정보를 제공하는 B41 원본은 상당수 존재한다**는 것이다. 원본을 다시 추출하는 작업과 게임 내 실행 조건을 확인하는 작업이 필요하다. 단순히 문장의 주어를 바꾸는 수정으로는 현실 용도의 혼입을 막을 수 없다.

## 실제로 확인된 문제

### 1. 기존 입력은 원본의 구체성을 충분히 보존하지 않는다

2,105개 중 **1,789개**에서 이번 점검이 지정한 상세 필드 중 하나 이상이 원본에는 있지만 `items_itemscript.json`에는 없었다. 모든 필드를 공개 설명에 넣어야 한다는 뜻도, 이 항목들의 현재 설명이 모두 틀렸다는 뜻도 아니다. 다만 사용자의 행동과 효과를 설명할 자료가 원본에 더 있다는 직접적인 근거다.

- `Base.Toolbox`: 원본에 `Capacity=8`, `WeightReduction=15`가 있지만 기존 itemscript 추출 입력에는 이 필드들이 없다. 보관·운반을 설명할 수 있는 구체적인 자료다. [원본](C:/Users/MW/Downloads/coding/PZ/scripts/clothing/clothing_bags.txt:392)
- `Base.Apple`: 기존 입력의 허기·갈증 수치 외에도 원본에는 영양 수치와 `EvolvedRecipe`에 연결된 요리 종류가 있다. 기존의 식사 준비라는 분류보다 더 구체적인 문장을 만들 자료다. 수치의 표시 단위와 조리 조건은 별도 확인해야 한다. [원본](C:/Users/MW/Downloads/coding/PZ/scripts/items_food.txt:1630)
- `Base.Hammer`: 기존 `uc.action.construction` 분류 외에, 원본 제작법에서는 못 박힌 야구방망이를 만드는 데 소모되지 않는 도구로 연결된다. 건축 단계의 필요 도구 선언도 있다. 이 연결을 보존해야 무엇을 할 수 있는지 설명할 수 있다. [제작법](C:/Users/MW/Downloads/coding/PZ/scripts/recipes.txt:47), [도구 그룹](C:/Users/MW/Downloads/coding/PZ/lua/server/recipecode.lua:39), [건축 단계](C:/Users/MW/Downloads/coding/PZ/scripts/multistagebuild.txt:4)

기존 `recipes_index_full.json`도 항목별 recipe/role/category/source 관계 중심이다. 결과물·재료 수량·유지/소모·기술·콜백 등의 원본 선언을 그대로 제공하는 입력과는 다르다. 이번 보고서는 해당 선언을 별도 근거 레코드로 보존했다.

### 2. 현실의 물건 설명을 게임 행동으로 바꾸면 주장이 추가된다

현재 공개 문장에는 `Base.Toothbrush`의 “이를 닦을 때 쓰는 칫솔이다”, `Base.Leash`의 “반려견에게 매는 목줄이다”, `Base.DogChew`의 “개가 씹는 장난감이다”가 있다. 이번 원본 대조에서 이 아이템들의 구체적인 해당 행동은 확인하지 못했다. 칫솔 원본에는 잡동사니 분류·이름·무게·외형 등의 정의가 있다. [칫솔 원본](C:/Users/MW/Downloads/coding/PZ/scripts/newitems.txt:1476), [목줄 원본](C:/Users/MW/Downloads/coding/PZ/scripts/newitems.txt:453)

이것을 “이를 닦을 수 있다”, “개에게 목줄을 맬 수 있다”로 변환하면 단순한 물건 정체성 설명을 게임 기능 주장으로 바꾸게 된다. 그런 재작성은 이번에 확보한 근거로 정당화할 수 없다. 반대로 후보 검색에 없다는 이유만으로 “아무 용도도 없다”고 단정해서도 안 된다.

비어 있지 않은 `primary_use`는 총 175개 문장으로 반복된다. 이 중 “작업” 또는 “용도에 맞게” 표현이 들어간 문장이 1,122개 아이템에 적용돼 있다. 현실 활동 또는 추가 효과를 연상시키는 지정 표현은 428개 항목에 걸리며, 현재 공개 본문에도 그 primary_use가 그대로 있는 항목은 403개다. **이 수는 문구 재검토 후보 수이며 확정 오류 수가 아니다.** 예를 들어 음식의 “먹거나 나눠 먹을 때”라는 공통 표현 317개도 포함된다. 전체 문장과 모든 적용 ID는 `primary_text_groups.md`에 있다.

### 3. 실제 작동은 명칭보다 좁을 수 있다

`Base.TirePump`의 현재 설명은 “차량 타이어의 공기압을 조절할 때 사용된다”다. 실제 Lua에서는 공기를 넣는 경로에 펌프 보유·장착 조건이 있고, 공기를 빼는 경로에는 같은 조건이 없다. 따라서 플레이어 관점의 문장은 “타이어에 공기를 넣을 수 있다”처럼 확인된 역할을 정확히 표현하는 편이 낫다. [공기 주입·배출 경로](C:/Users/MW/Downloads/coding/PZ/lua/client/Vehicles/ISUI/ISVehiclePartMenu.lua:259)

이 예는 개별 호출 경로를 추가로 읽어 확인했다. 전체 2,105개에 대해 같은 수준의 호출·조건·결과 추적을 완료한 것은 아니다. 보고서의 Lua 후보 수를 검증된 기능 수로 해석하면 안 된다.

### 4. 원본에 있다는 사실과 현재 플레이에서 사용할 수 있다는 사실도 구분해야 한다

23개 항목은 원본 item 선언에 `Obsolete`/`OBSOLETE=true`가 있다. 이것만으로 실제 획득·실행 가능성을 확정하지 않았으며 추가 확인 대상으로 남겼다. 복잡한 동적 레시피 그룹, 비활성 메뉴 분기, Java 엔진의 처리도 같은 이유로 원본 등장 여부만으로 설명을 생성하면 안 된다.

## 재작성과 툴팁 반영에 필요한 조치

1. 원본에서 아이템별 **행동, 대상, 결과/효과, 조건, 재료/도구 역할, 소모 여부, 근거 위치**를 보존한다. 결과 수치를 찾지 못했다면 임의로 추가하지 않는다.
2. 실행 경로까지 확인한 기능과, 선언·분류만 있는 후보를 분리한다. 아이템 이름과 현실 상식으로 빈칸을 채우지 않는다. 미확인 항목은 기능 주장을 보류한다.
3. 같은 문장을 쓰는 아이템도 각각 근거를 대조한다. 분류가 같다는 이유로 전부 같은 기능을 부여하지 않는다.
4. 승인된 설명 입력과 DVF 산출물을 갱신한 뒤, 툴팁 S2 소유 입력·번역·정적 데이터까지 기존 경로로 다시 생성하고 배포 결과를 대조한다.

현재 툴팁 S2 생성 코드는 DVF rendered의 `core_source_fact_ids`로 선택 여부를 판단하고 facts의 `primary_use`를 한국어 원문으로 가져온다. 따라서 `dvf_3_3_rendered.json`의 문장만 고치는 것으로 툴팁 반영이 끝나는 구조가 아니다. [생성 코드](C:/Users/MW/Downloads/coding/PZ/Iris/tooling/src/iris_tooling/build/build_layer3_english_localization.py:861)

이번에는 설명·facts·툴팁을 수정하거나 새 근거를 제품의 승인된 데이터로 채택하지 않았다. 별도 보고서만 작성했다.

## 검증과 한계

`inspect_all.py` 및 `validate_report.py`를 각각 `uv run --no-project python -B <경로>`로 실행했고 모두 종료 코드 0이었다. 2,105개 ID의 누락·중복, 현재 설명 일치, 근거 참조의 양방향 연결, 원본 위치, 원본 1,041개와 현재 입력의 해시 일치를 검사했다. 검증된 근거/후보 레코드는 22,717건이다.

해석하지 못한 레시피 토큰은 42건이며 별도 파일에 남겼다. 여기에는 `Water` 28건과 조건부 의류 찢기 등의 동적 그룹이 포함된다. 일반 타입의 공통 동작, 전체 스프라이트 속성, Java 엔진 내부, 모든 Lua 호출 관계는 이번 스캔에서 완전히 해석하지 않았다. 획득처 문장도 이번 용도·효과 점검 범위 밖이다. 실제 게임 실행 검증은 수행하지 않았다.

따라서 이번 결과는 **전체 항목에 대한 1차 근거 점검 완료**이며, **전체 설명의 사실성 보장 완료**는 아니다.
