# 문제 2 — 의미 블록 기반 compact·expanded 설명 조합 규칙과 생성기

## 1. 문제명과 입력 기준

- 문제 ID: DVF-COMPOSITION-2
- 입력 버전 / 기준일: v2 / 2026-09-10
- 대상: Iris DVF의 사용자 설명 배치·합성·한영 문장 생성
- 기준 상태: 문제 1은 완료됐다. 채택된 r6 사실을 설명 블록으로 묶는 공통 의미 규칙과 실제 전체 적용 결과·reader가 확보됐다. 이번 문제는 그 블록을 어떤 한국어·영어 문장으로 표현할지에 관한 공통 조합 규칙과 생성기를 구현한다. 기존 A의 장문 설명과 현재 제품 표시가 이 완료로 고쳐진 것은 아니다.

개정 근거는 [문제 1 Walkthrough](iris_layer3_composition_walkthrough.md)다. v1의 미확보 선행 조건을 실제 완료 입력으로 갱신하고, 문제 2의 문장화 책임과 문제 3의 별도 언어 품질 검수·수정 책임을 명확히 했다. Walkthrough는 구현 이력이며 새로운 실행 지시나 Gate를 추가하는 문서로 취급하지 않는다.

두 로드맵 작성자에게 같은 v2와 공통 문서를 제공한다. 필요한 현재 상태와 사용자 정의는 이 문서 안에 포함한다. 과거 A/B 테스트 성공은 이 생성기의 설명 품질 근거가 아니다.

## 2. 문제 정의

### 현재 상태와 기대 상태의 차이

실패가 확인된 기존 r6 표현기는 compact expression들을 공백으로 이어 붙이고 문자열이 있으면 `logical_rows=1`을 부여했다. 일부 기능 묶음은 있지만, 어떤 의미와 조건을 어느 깊이로 합성할지에 대한 공통 조합 규칙이 부족하다. expanded에도 비슷한 맥락과 조건이 여러 블록에서 반복된다.

문제 1은 “무엇을 어떤 의미 관계로 묶을지”를 해결했다. 아직 문장 골격, 주어·서술어 선택, 표현 순서, 접속, 반복 생략, 조건을 붙이는 위치와 두 언어의 자연스러운 표현 규칙은 이 결과만으로 결정되지 않는다.

기대 결과는 **문제 1의 같은 의미 구조에서 짧은 DVF 설명과 의미별 상세 설명을 각각 독립 생성하는 공통 문장 조합기**다. 모든 fact 문장을 짧은 문장으로 바꾸어 전부 이어 붙이는 것은 해결이 아니다. 문구를 자르거나 대표 기능 하나를 고르는 것도 해결이 아니다.

### 영향과 필요성

r6를 공급한 B 인게임 후보에서 판자의 Tooltip이 장문이 되는 실패가 관찰됐다. 판자의 원본 S2도 KO 341자·11문장, EN 770자·11문장이어서 공급 손실만의 문제가 아니다. 이 입력을 유지한 채 Tooltip 폭이나 Menu 간격만 조정해서는 설명 품질을 회복할 수 없다.

## 3. 필요한 배경과 현재 상태

| 요소 | 역할과 경계 |
|---|---|

| compact / S2 | 아이템을 처음 이해하기 위한 Tooltip 둘째 줄의 DVF 설명. 상세의 단순 복사/절단물이 아니다. |

| 표현 배치/생략 | 상세 정보를 더 깊은 설명에 두는 결정. 독립 용도를 primary_use로 대체하거나 필요한 조건을 없애는 결정과 다르다. |
| Layer 4 | 정확한 레시피·우클릭·자유 조리의 관계와 절차. Layer 3의 기능 이해 조건과 구분한다. |

### 문제 1에서 확보한 입력과 한계

`Iris/build/description/composition/blocks.json`은 schema `iris-layer3-composition-v1`, contract version `1`의 실제 인계 자료다. `composition_results.read_result()`로 읽는다. 제품 current를 교체한 자료가 아니라 저장소 내부 개발·검증 입력이며, 후속 개발을 위해 별도 adoption/seal을 선행할 필요는 없다.

대상은 2,105 exact FullType이며 semantic 28,145개와 acquisition 1,057개, 총 29,202개 accepted fact를 보존한다. 블록 10,304개 중 복수 branch 블록은 1,591개다. 이 수치는 의미 전수 정확성이나 문장 품질 점수가 아니다.

- `blocks/branches`: 함께 설명할 의미와 그 안의 독립적인 대상·행동 분기다. 하나의 block을 한 문장이나 화면 한 줄로 고정하지 않는다.
- `relations`: 맥락·역할의 세분(refinement), 대상별 변형(context_variant), 명시적 기능→효과(result), 복합 기능(compound), 복수 획득 경로(alternative)를 보존한다. 동일 조건은 원 사실 참조를 유지하며 중복을 정리했다.
- `qualifiers`: 원래 적용 사실·branch·block 참조를 가진 item-level 조건이다. 한 block의 모든 branch에 적용되는 조건과 일부 또는 서로 다른 block에 적용되는 조건을 구분한다. 적용 범위는 exact refs를 따르며 단순 공통 조건으로 기능을 합치지 않는다.
- `separate_block_refs/unresolved_relations`: 별도로 남겨야 할 의미와 근거가 부족한 실제 관계 후보다. 창낚시 기능과 내구도 감소 사이 인과를 확정하지 못한 14건은 별도 표현해야 한다. A 전체 조사 미해결이 14건이라는 뜻은 아니다.

구체적으로 연료·불쏘시개·마찰 점화는 대상별 분기를 묶고, 확인된 맥락 포함 관계는 명시된 역할 집합이 같을 때만 적용한다. 기능·효과는 근거를 확인한 exact 대응표로 연결한다. 노트의 보기·쓰기·페이지/제목·잠금은 복합 블록이지만 각각의 조건은 유지한다. 등록된 관계 밖의 의미를 단어 유사성이나 같은 조사 규칙만으로 합치지 않는다.

최종 집중 검사 `exit 0, 1 passed in 15.34s`는 전체 사실 보존·참조/조건 구조·대표 사례·reader를 확인했다. 모든 관계의 인간 의미 전수 검수, upstream 게임 사실 진위, KO/EN 자연스러움, 제품 UI는 검증하지 않았다. 문제 1의 규칙을 입력으로 사용하되 발견된 결함까지 무조건 정답으로 고정하지 않는다.

사용자가 재확인한 Tooltip은 최대 4줄이며, 첫째 줄은 2계층 소분류, 둘째 줄은 DVF 설명, 셋째 줄은 획득 장소, 넷째 줄은 4계층 상호작용(레시피·우클릭 행동·자유 조리)의 랜덤 표시다. 비어 있지 않은 장문에 `logical_rows=1`을 붙이는 것으로 둘째 줄의 설명 요구를 충족하지 않는다. 기존 표시 정책을 바꾸거나 Tooltip을 넓혀 표현 결함을 가리는 작업은 요구하지 않는다.

모든 아이템의 획득을 조사하되 모르면 추측하지 않는다. 확인된 획득 맥락은 Menu에서 열람 가능해야 한다. Tooltip 획득 장소는 셋째 줄의 책임이므로 둘째 줄에 획득 정보를 무조건 누적하지 않는다.

과거 실패 비교 자료는 `Iris/_docs/authority/dvf/layer3_expression/successors/r6/descriptions.json`이며 exact FullType 2,105개의 KO/EN S2·expanded를 담는다. 검수에서 KO S2 1,553개가 3문장 이상, 1,054개가 5문장 이상이었다. 이는 물리 줄 수 합격 판정이 아니라 부담 지표다. KO 문장 경계 누락은 S2 129개, expanded 379개에서 확인됐고, expanded 블록 간 동일 문장 반복은 614개였다. 전체 게임 사실 진위/모든 영어 상세 문장을 전수 검증한 결과는 아니다.

판자는 목공 작업·목공 건축·건축 작업 등 맥락을 나열하고 덫 일반 조건·운전 제한·부목 제거/치료 계수를 함께 출력한다. 의류는 세척·연료·불쏘시개·직물·착용·패딩 정보를 반복하며, 켜진 촛불 S2는 KO 806자·27문장이다. 공통 기능이 사실로 존재한다는 것 자체를 오류나 삭제 대상으로 판정한 것은 아니다.

짧게 만든 검수 예시에서도 오류가 드러났다. “수리 가능한 망치”를 “수리에 사용하는 망치”로 바꾸거나 필기구 조건을 메모 잠금까지 붙인 문장은 의미를 바꾼다. 단순 문장 단축·유창함만으로 생성기를 수락할 수 없다.

## 4. 목표

- 확정된 의미 블록을 문장으로 옮기는 공통 규칙을 구현한다. 문장 골격·표현 순서·병렬 연결·주어/서술어 반복 생략·조건 귀속·구두점·언어별 표현을 다루고 compact와 expanded의 정보 깊이를 구분한다.
- compact는 여러 독립 용도를 알아볼 수 있게 짧고 자연스럽게 표현하며, 해당 의미를 성립시키는 필수 조건을 보존한다.
- expanded는 모든 채택된 사용자 의미에 접근할 수 있게 구성하고 공통 조건을 적절한 범위에서 한 번 설명한다.
- KO/EN 각각 자연스러운 문장을 만들되 역할·조건·부정·대안·결과의 의미를 같게 유지한다. 한국어를 영어 어순으로 직역하거나 내부 식별자를 번역한 표현을 그대로 나열하지 않는다. 문제 3에서 검수할 원문을 그대로 열람할 수 있어야 한다.
- 의미 손실 없이 만들 수 없는 출력은 이유를 드러내고 문제 1 또는 근거 책임으로 반환한다. 무조건 긴 문단 출력이나 조용한 누락으로 성공 처리하지 않는다.

길이 예산과 의미 압축의 구체 방법은 기존 Tooltip의 실제 조건을 바탕으로 설계한다. 고정 글자 수·최대 문장 수를 임의의 완전한 품질 기준으로 만들지 않는다. 어려운 아이템도 Tooltip 정의를 완화하거나 임의 primary_use를 도입하는 예외로 처리하지 않는다.

## 5. 대상, 책임 경계 및 범위 밖

### 포함 대상

의미의 compact/expanded 배치, 기능·조건 합성, 공통 조건의 반복 방지, 자연어 템플릿과 접속/구두점, KO/EN 대응, 생성 결과의 사실/블록 관계 보존을 포함한다. 필요한 출력 계약과 기존 표현기 수정은 가능하다. 구체 함수·저장 파일·UI 그룹 형식은 계획에서 정한다.

세부 정보를 S2에서 생략할 때는 상세에서 어떤 의미로 보존되는지 확인 가능해야 한다. Layer 4와 겹친다는 이유로 정보를 버리거나 존재하지 않는 상세 화면으로 이관 완료를 주장하지 않는다. 범위상 필요한 Layer 3 조건은 유지하고 정확한 목록/절차의 소유권을 침범하지 않는다.

### 범위 밖

문제 1의 사실 통합 규칙을 문장 편의를 위해 임의 재정의하는 것, 모든 미해결 질문의 재조사, 전체 2,105개 최종 문장 품질 수락(문제 3), Tooltip 조립/Alt/랜덤 선택 재구현(B), Menu UI 구조화(C), 추천·효율 평가·아이템별 수작업 대체문 데이터베이스는 제외한다. 실제 결함을 재현하고 규칙을 확인할 생성 예시는 본 문제에 포함한다.

### 작업 조건

Windows/PowerShell과 문제 1 인계 결과·기존 표현기·검수 자료를 사용할 수 있다. 원본 r6는 역사로 보존하고 필요한 새 결과는 정당한 후속 자료로 구분한다. 이 문서는 새 환경·외부 파일 접근·커밋·제품 전환을 승인하지 않는다.

## 6. 선행 조건과 의존 관계

| 관계 | 진행 조건 |
|---|---|
| 문제 1 → 문제 2 | 완료. blocks.json과 reader, 관계/조건 계약을 소비한다. 생산기나 문제 1의 전체 검사를 기본 재실행하지 않는다. 의미 구조 결함이 발견되면 표현 우회 대신 해당 책임의 최소 수정으로 환류한다. |
| 문제 2 → 문제 3 | 실행 가능한 생성기, 2,105개 KO/EN compact·expanded 결과 및 부재/실패 상태, 표현과 의미 블록의 연결을 넘긴다. 문제 3은 동일 결과를 재사용한다. 대표 예시의 품질 확인과 전체 문장 품질 수락을 구분한다. |
| 기존 B/C | 공급·reader 기반을 재사용할 수 있도록 입력 관계를 설명한다. 실제 Tooltip/Menu 연결은 이 문제에서 수행하지 않는다. |

전체 재생성에서 나온 결함은 문제 1/2의 해당 공통 규칙으로 돌아가 정정한다. 문제를 분리했다는 이유로 이미 알게 된 생성 결함을 후속 단계에 떠넘기지 않는다.

| Profile/내부 용어를 그대로 설명하지 않음 | 사용자 설명은 실제 기능과 맥락을 설명해야 한다. `가공 대상`, `지원하는 물체` 등 추상 템플릿을 기계적으로 나열하지 않는다. |
| 정보 부재와 생성 실패 구분 | 과거 r6 S2 공백 121개는 당시 compact 비적용 110과 upstream gap 11이었다. 과거 compact 비적용을 새 의미 구조의 설명 불가나 전체 의미 부재로 승계하지 않는다. 정상 부재는 근거를 확인하고 새 생성 실패와 구분한다. |
| 사실 보존과 정보 배치 구분 | S2에서 상세를 생략해도 해당 사용자 의미의 접근 경로는 유지한다. audit만 남겨 놓고 사용자 열람 보존이라고 하지 않는다. |

## 8. 참고 아이디어와 불확실성

| 질문 | 영향과 단서 |
|---|---|
| 어떤 조건이 첫 이해에 필수인가 | 일반 절차/공통 전제와 기능의 진위를 바꾸는 조건을 구분해야 한다. 빈도만으로 결정하지 않는다. |
| 실제 Tooltip의 허용 표시 조건은 무엇인가 | 기존 폰트·폭·표시 방식 확인이 필요하다. 미확인 물리 줄 수를 문자열 지표로 대체하지 않는다. |
| 여러 독립 용도를 어느 추상도로 합칠 수 있는가 | 구체 기능을 거짓 상위 개념으로 일반화하지 않아야 하며 문제 1 규칙에 의존한다. |
| 영어의 더 긴 표현에서 같은 의미를 어떻게 보존할 것인가 | 문자수 동일성을 강제하지 않고 자연스러운 별도 문장화를 설계한다. |

품질 검수 보고서의 단축 예시는 검증된 대체문이 아니며 조건/기능 누락을 재검토해야 한다. 이를 정답 fixture로 복사하지 않는다.

## 9. 완료 조건과 필요한 증거

| 조건 | 필요한 결과 |
|---|---|
| G1. 실제 공통 조합기 | 의미 블록에서 compact/expanded를 독립 생성하며 기능 합성·조건 배치·반복 방지 규칙이 구현돼 있다. 순서대로 join하는 함수를 새 이름으로 감싸는 것으로 충족되지 않는다. |
| G2. 의미와 언어 품질 | 다양한 기능/조건 조합의 실제 KO/EN 결과에서 간결성·자연스러움과 역할/조건 보존을 함께 확인한다. 단순 ref parity나 문장 수만으로 통과하지 않는다. |
| G3. 전체 검수 가능한 전달 | 2,105개 KO/EN compact·expanded 생성 결과와 부재/실패 사유가 있어 문제 3이 원문을 그대로 검수할 수 있다. 입력 의미와 출력의 연결, 사용한 규칙 및 미결 한계가 명확하며 대표 예시만 넘기지 않는다. |

세 결과는 별도 Gate 수를 지정하지 않는다. 규칙 구현과 필요한 대표 결과 확인을 같은 실행에 묶고 기존 관련 검사를 재사용한다. 검사는 구현 종료 시 필요한 범위에 묶고 계획 밖 중간 테스트를 하지 않는다. 저장소 전체 Run A/B + comparator, 문제 1 재수락, historical replay, 새 proof/봉인 tree·A 전수 검사·전체 suite 반복은 이번 표현 변경만으로 요구하지 않는다. 실제 적용 계약이 있는 경우에만 접점과 최소 검사를 계획에서 명시한다. 여기서의 완료는 생성기 확보이며 전체 corpus 품질 수락이나 B/C 완료가 아니다.

## 10. 입력 전달 전 확인

의미 규칙과 문장 조합, 의미 보존과 전부 출력, 실제 네 줄 정의와 logical_rows를 구분했다. v2는 문제 1의 완료 입력과 검증 한계를 반영하고 문장 표현 규칙을 이번 책임으로 명시했다. 구체 템플릿·글자 수·UI 변경·테스트 개수를 미리 고정하지 않았다. 생성기의 결과 책임과 후속 전수 품질 검수의 범위를 명확히 했다.
