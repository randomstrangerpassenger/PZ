# 문제 A — DVF 기존 설명 이관 누락과 조사 질문 판정 복구

## 1. 문제명과 입력 기준

- 문제 ID: DVF-RECOVERY-A
- 입력 버전 / 기준일: v1 / 2026-09-07
- 대상: Iris DVF의 비획득·획득 조사, 사실 채택, 설명 생성 및 기존 설명 이관
- 기준 상태: 기존 `primary_use` 중심 설명을 다중 의미 구조로 대체하는 후보가 만들어졌으나, 설명 공백이 증가했다. 이 문서는 후속 정정 요구다. 공통 문서에 기록된 DVF-L3-01~06의 단계별 complete를 설명 이관 및 대체 제품의 완료로 전제하지 않는다.

이 문서는 웹 로드맵 작성자가 저장소·이전 대화·문제별 원본 파일을 읽지 않아도 사용할 수 있는 입력이다. 동일 v1과 동일 공통 문서를 두 작성자에게 전달한다. 아래 수치는 기준일의 로컬 데이터 집계와 코드 표본 검토 결과이며 새 검증 PASS가 아니다.

## 2. 문제 정의

### 현재 상태와 기대 상태의 차이

기존 DVF는 아이템의 대표 용도인 `primary_use`를 중심으로 설명했다. 사용자가 요구한 변경은 대표 용도 하나를 선정하는 제한을 폐기하고, 확인된 복수 역할·조건·획득·고유 특성을 보존하는 것이다. 기존에 확인한 의미를 삭제하는 것이 목적은 아니다.

새 후보는 새 조사에서 채택한 사실만으로 설명을 생성한다. 기존 문장은 근거를 찾기 위한 단서로 취급하고 자동 승계하지 않는다. 이 원칙 자체는 타당하지만, 기존 설명의 근거를 충분히 재확인·이관하지 못한 상태에서 빈 새 결과가 대체 설명으로 연결되었다. 이전 데이터는 2,105개 중 빈 설명이 6개이고 새 데이터는 552개다. 순증 546개는 집계 차이이며, 정확한 아이템별 전환 집합이나 의미 손실 수는 아직 대조하지 않았다.

사용자 요구는 근거 있는 기존 의미를 새 다중 의미 구조로 이관하고, 잘못된 주장은 근거에 따라 정정하며, 미판정 이관 공백을 전체 대체 완료로 취급하지 않는 것이다. 또한 질문은 확인 가능한 범위의 답을 근거로 종결할 수 있어야 한다. 통과 수를 늘리기 위한 기준 완화는 요구가 아니다.

### 영향과 필요성

확인된 영향은 새 설명 데이터의 공백 증가다. 문장이 남은 아이템에서도 특정 역할·조건·획득 정보가 사라졌을 가능성은 미확인이다. 이 상태의 후보를 대체 제품으로 채택하면 기존에 접근 가능했던 정보를 잃을 위험이 있다. 실제 사용자 설치본의 전환 여부는 확인하지 않았다.

### 질문 판정 표본에서 확인한 사실

현재 문제 3 생산 코드는 조사 경로별 공통 dependency를 정하고, 그 경로의 개별 질문에 미해결·부분 coverage를 기본 부여한다. 확인된 예외는 `CantEat` 음식의 native 섭취 기능·효과 질문 적용 제외다. 따라서 미해결 9,900개를 모두 개별적으로 확정된 자료 부족으로 읽을 수 없다.

노트류 Notebook·Journal·Doodle·SheetPaper2의 읽기/기록 기능·효과·조건 12개 질문은 모두 일반 책 읽기 경로인 `ISReadABook_SkillBook_and_ReadLiterature`를 장애물로 가진다. 그러나 원본 Lua에는 별도의 노트 읽기/편집 분기, 필기구·잠금에 따른 편집 가능 여부, 저장된 페이지를 표시하는 창이 있다. 기존 채택 사실은 기록 가능·편집 제약이며 열람 기능은 별도 사실로 없었다. 관련 원본 세 파일은 기존 source binding과 현재 해시가 일치했다. 이는 추가 사실과 질문별 장애물 재검토 후보이지, 12개 질문 전부의 해결을 입증한 결과는 아니다.

반대로 정확한 선언 부재·중복 선언, 엔진 구현·동적 등록·실행 시점 상태 때문에 실제 근거가 부족한 사례도 있다. 공통 장애물이 있다는 이유만으로 모든 미해결을 오류로 분류하지 않는다.

## 4. 목표

- 기존 설명과 새 설명 사이의 아이템별·의미별 차이를 확인하고, 근거 있는 기존 의미를 다중 사실 구조로 이관한다.
- 개별 질문의 범위와 근거에 맞게 판정하여, 확인한 답과 실제로 남은 범위를 구분한다.
- 추가 채택·정정된 사실이 compact/expanded에 적절히 반영되게 한다.
- 미확인 이관 손실과 정당한 정정·제거를 구별하고, 남은 공백을 완료 주장에 숨기지 않는다.

미해결 0, 전 아이템 최소 문장 수, 기존 문장 무조건 보존 등의 수치 목표는 없다. 구체적인 작업 분해·조사 순서·산출물 형식은 로드맵에서 설계한다.

## 5. 대상, 책임 경계 및 범위 밖

### 포함 대상

기존/새 2,105개 대상의 설명과 근거, 비획득·획득 결과, 질문 정의·판정 및 사실 결속, 설명 생성과 이관 상태가 대상이다. 전수 차이 식별과 원인에 맞는 조사·수정이 필요하며, 단순히 552개 공백만 채워 문장이 남은 아이템의 의미 손실을 놓쳐서는 안 된다.

### 범위 밖

- Tooltip 생산·Recipe·current 소유권 복구는 문제 B다.
- Menu 의미 구조 전달·가독성은 문제 C다.
- 외부 모드 전수 조사, 권장·효율 평가, 게임 상태 변경은 포함하지 않는다.
- 모든 동적 행동의 완전한 해명을 목표로 범위를 무한히 확대하지 않는다. 필요한 구체적 근거 조사는 포함된다.

### 작업 조건

후속 Codex 실행은 Windows/PowerShell 저장소에서 원본 scripts·Lua, 조사 corpus와 생산 코드에 접근할 수 있다. 필요한 엔진 구현이나 특정 게임 빌드의 가용성은 미확인이다. 웹 작성자가 저장소 원본을 재감사할 수 있다고 가정하지 않는다. 이번 산출물은 실행 계획이나 배포 명령이 아니다.

## 6. 선행 조건과 의존 관계

기존 설명·새 사실·새 표현의 동일 대상 비교가 이관 판정의 입력이다. 실제 기준 파일의 identity는 후속 계획에서 확인한다. A의 추가·정정 사실은 설명 생성이 소비하고 B의 S2 입력과 C의 expanded 입력으로 이어진다. B/C 구조 수정에 A의 모든 질문 종결을 선행 조건으로 강제하지 않는다. 최종 대체 제품의 설명 보존 주장은 실제 통합 입력으로 확인해야 한다.

## 10. 입력 전달 전 확인

질문/아이템/사실 단위, 기존 제품과 후보, 확정 관찰과 표본 가설을 구별했다. 기존 설명 이관 요구와 완료 의미를 본문에 포함했으며, 저장소 접근을 웹 작성자의 전제로 두지 않았다. 구체적 단계 수·도구·검증기·중간 파일 형식은 고정하지 않았다.
