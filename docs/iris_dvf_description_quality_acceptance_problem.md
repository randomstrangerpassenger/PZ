# 문제 3 — 전체 생성 문장의 의미·언어 품질 검수와 결함 수정·B/C 인계

## 1. 문제명과 입력 기준

- 문제 ID: DVF-COMPOSITION-3
- 입력 버전 / 기준일: v3 / 2026-09-10
- 대상: 새 의미 통합·설명 조합 규칙의 전체 아이템 적용 결과와 품질 수락
- 기준 상태: 문제 1과 문제 2는 완료됐다. 문제 2는 공통 문장 조합기를 구현하고 2,105개 아이템의 KO/EN compact·expanded 8,420개 상태를 저장했다. 모든 아이템에 설명이 존재하거나 전체 원문의 품질이 수락됐다는 뜻은 아니다. 본 문제는 현재 저장된 실제 문장과 부재 사유를 검수하고, 발견한 결함을 공통 규칙에 반영해 품질을 수락하는 단계다.

개정 근거는 [문제 2 Walkthrough](iris_dvf_description_composition_walkthrough.md)와 사용자의 전체 설명 범위 확인 및 문장 품질 검수 요구다. v3는 문제 2의 완료 입력·실제 상태 분포·이미 수정한 공통 규칙·남은 검수 대상을 반영한다. Walkthrough의 구현 보고와 요구사항을 구분하며 새 Gate나 authority를 추가하는 지시로 취급하지 않는다.

같은 v3와 공통 문서를 두 로드맵 작성자에게 전달한다. B는 검수된 S2의 Tooltip 연결, C는 검수된 expanded의 Menu 연결을 맡는다. 본 문제는 두 제품 작업을 대체하지 않는다.

## 2. 문제 정의

### 현재 상태와 기대 상태의 차이

기존 A에서는 사실 참조·문자열 대응·공백 감소와 일부 예시 정정을 확인했지만 전체 설명의 가독성과 품질을 충분히 검수하지 못했다. B는 그 문자열을 정확히 공급해도 장문 Tooltip을 만들었다. 따라서 새 공통 규칙이 생겨도 대표 몇 개의 성공만으로 같은 실패를 반복할 수 있다.

필요한 결과는 **문제 2에서 생성한 전체 문장을 읽고, 어색함·간결성·자연스러움·번역체 여부와 의미 보존을 검수하여 해결 가능한 결함을 수정한 설명 자료**다. 검수 보고서 작성만으로 알려진 설명 결함을 남겨 두고 완료하는 과제가 아니다.

### 영향과 필요성

r6 판자의 실제 Tooltip은 장문이며 원문도 KO 341자·11문장이다. 기존 Menu는 predecessor를 표시해 새 expanded가 연결되지 않았고, 이 화면을 A 결과가 표시된 증거로 볼 수 없었다. 새 설명 수락과 제품 연결 상태를 분리해 B/C에 정확한 입력을 넘겨야 한다.

### 문제 2의 실제 검수 입력과 상태

주 검수 입력은 `Iris/build/description/composition/descriptions.json`, schema `iris-layer3-descriptions-v1`이다. 과거 r6의 동명 파일과 구분한다. `description_composition_results.read_result(root)`는 저장된 원문과 구조를 읽으며 producer나 문제 1 입력 reader를 호출하지 않는다. 검수 착수나 원문 열람을 위해 결과를 재생성할 필요가 없다.

| 표면 | KO present / absent / failed | EN present / absent / failed |
|---|---|---|
| compact | 1,984 / 121 / 0 | 1,984 / 121 / 0 |
| expanded | 2,043 / 62 / 0 | 2,043 / 62 / 0 |

**2,105개 전부 처리**와 **2,105개 전부 설명 존재·품질 합격**은 다르다. 현재 8,420개 상태 중 문장이 있는 표면은 8,054개이고 부재 표면은 366개다. 채택된 블록이 없는 아이템 62개, 획득 블록만 있는 아이템 59개이므로 compact 부재는 121개다. 획득 전용 59개는 expanded 원문이 있다. 과거 compact 비적용 110/upstream gap 11 판정을 현재 부재 이유로 복사하지 않았다.

이 수치는 검수 착수 기준이며 수정 후 고정해야 하는 quota가 아니다. `present`는 생성 상태이지 품질 합격이 아니고 `failed=0`도 언어 결함이 없다는 뜻이 아니다. 62개에 입력이 없다는 사실은 아이템에 설명할 기능이 없거나 조사 완료라는 뜻이 아니다. 부재는 현재 입력과 사유의 일치를 확인하고, 입력 누락과 생성 누락을 구분한다. 전체 미조사 사실을 새로 조사하여 공백을 0으로 만드는 작업은 이 문제에 자동 편입하지 않는다.

원문 대조에 필요한 구조는 다음과 같다.

- `items[].item_id`와 `locales.ko/en`의 compact/expanded 상태·text·segments로 실제 출력을 읽는다.
- Segment의 block/branch/fact/qualifier/relation refs로 의미를 대조한다. 조건 원문은 item-level `qualifiers`에 있고 exact application을 유지한다.
- Compact의 `qualifier_dispositions`는 `compact_core`(본문 통합), `compact_summary`(짧게 표현), `expanded`(상세 배치)를 구분한다. 이 기록과 실제 문장이 일치하는지 확인하며 기록 자체를 의미 보존 증거로 대체하지 않는다.
- `detail_links`가 가리키는 같은 언어의 expanded segment에서 상세가 실제로 읽히는지 확인한다. 링크 존재와 자연어 의미 보존은 별개다.
- 입력·생성기 identity는 결과 안에 있다. 검수 대상과 수정 후 결과를 구분하는 데 재사용하고 별도 봉인/receipt를 만들지 않는다.

문제 2의 최종 집중 검사 기록은 exit `0`, `1 passed in 4.53s`다. 한 실행에서 전체 생성·입력 직접 대조·저장·읽기와 작은 의미 반례를 공유했다. 수정 때문에 같은 명령을 재실행했으며 세션 전체 생산이 단 한 번이었다는 뜻은 아니다. 대표 원문은 구현자 자체 검토와 감독을 거쳤지만 전체 언어 품질 수락은 하지 않았다. 이미 검토한 대표도 이번 전체 검수에서 면제하지 않는다.

### 수정된 공통 규칙과 남은 검수 대상

문제 2는 동일 역할의 활동 병렬화, 기능/효과와 국소 조건의 문장 합성, 일반 조건 경로 복귀, 개요/상세 배치를 구현했다. 조건 공유만으로 인과를 만들지 않으며 예상하지 않은 조건이 추가되면 고정 문장 틀 대신 조건 보존 경로로 돌아간다. 대표 사례에서 발견한 결함은 특정 FullType 대체문이 아니라 관련 기능군의 규칙으로 수정했다.

| 기준 사례/수정 범위 | 현재 처리와 이번 문제의 검수 초점 |
|---|---|
| 판자·망치 | 활동별 재료/도구 역할과 용도를 조합하고 개별 제작·회수 절차는 상세에 뒀다. 한 문장으로 길게 연결했을 뿐인지, 독립 용도와 역할을 알아볼 수 있는지 확인한다. |
| 노트·연료/불쏘시개 | 보기·쓰기·잠금 조건을 구분하고 점화 도구 조건은 불쏘시개에만 붙인다. 실제 KO/EN의 수식 범위와 반복을 확인한다. |
| 점화 도구 9개 | 공통 점화 목적 아래 대상을 모으고 수단별 조건을 상세에 뒀다. 긴 대상 나열의 읽기 부담, 허위 대상/수단 조합, 사용자가 이해하기 어려운 표현을 살핀다. |
| 물 용기 49개 | 보관·운반·사용 목적을 합성하고 오염수 위험을 남겼다. 수치·개별 제작 상세를 뺀 개요가 모호하거나 과장되지 않는지 확인한다. |
| 조명·상태 전환 | 조명 자체 점화/소화·장착 해제·건전지 운영을 상세에 배치했다. “휴대 조명을 조작” 같은 표현이 실제 기능을 이해시키는지, 상태 의존을 왜곡하지 않는지 확인한다. |
| 독서·의료·시비·흡연·차량·총기 | 결과 관계와 국소 조건을 표현한다. 핵심 효과가 빠지지 않았는지, 내부 수치/용어·조건 나열·직역투가 남았는지 확인한다. |

검수 기준을 이해하기 위한 현재 원문 예시는 다음과 같다. 고정 정답이나 이미 합격한 문장이 아니다.

- 판자 KO: “건축·금속 가공·목공에 쓰는 재료이며, 차량 밖 근접 공격, 머리·몸통 외 골절의 부목 적용에 쓰거나 연료로 소모할 수 있다.”
- WaterPot KO: “물을 보관·운반하며, 담긴 물은 작물 급수·차량 혈흔 세척·소화·갈증 해소에 쓸 수 있다. 오염된 물을 마시면 중독될 수 있다. 조리 재료 추가에 쓰는 바탕 재료다.”
- CandleLit의 조명 표현 KO/EN: “손에 들거나 장착한 상태에서 휴대 조명을 조작할 수 있다.” / “It offers portable-light controls while held or attached.”

긴 나열·추상 명사·직역투는 검토할 위험이지 해당 유형 전부의 오류 확정이 아니다. 해결에는 생성기의 공통 규칙/어휘/문법 수정을 사용한다. 코드에서 실제 역할은 `description_composition_planner`(배치), `families`(기능군 합성), `lexicon`(어휘/조건 배치), `ko/en`(문법), `model/results`(구조/저장)로 나뉜다. 상세 구현 방안이나 수정 파일 수는 후속 계획에서 정한다.

### 문제 1에서 확보한 입력과 한계

`Iris/build/description/composition/blocks.json`은 schema `iris-layer3-composition-v1`, contract version `1`의 실제 인계 자료다. `composition_results.read_result()`로 읽는다. 제품 current를 교체한 자료가 아니라 저장소 내부 개발·검증 입력이며, 후속 개발을 위해 별도 adoption/seal을 선행할 필요는 없다.

대상은 2,105 exact FullType이며 semantic 28,145개와 acquisition 1,057개, 총 29,202개 accepted fact를 보존한다. 블록 10,304개 중 복수 branch 블록은 1,591개다. 이 수치는 의미 전수 정확성이나 문장 품질 점수가 아니다.

- `blocks/branches`: 함께 설명할 의미와 그 안의 독립적인 대상·행동 분기다. 하나의 block을 한 문장이나 화면 한 줄로 고정하지 않는다.
- `relations`: 맥락·역할의 세분(refinement), 대상별 변형(context_variant), 명시적 기능→효과(result), 복합 기능(compound), 복수 획득 경로(alternative)를 보존한다. 동일 조건은 원 사실 참조를 유지하며 중복을 정리했다.
- `qualifiers`: 원래 적용 사실·branch·block 참조를 가진 item-level 조건이다. 한 block의 모든 branch에 적용되는 조건과 일부 또는 서로 다른 block에 적용되는 조건을 구분한다. 적용 범위는 exact refs를 따르며 단순 공통 조건으로 기능을 합치지 않는다.
- `separate_block_refs/unresolved_relations`: 별도로 남겨야 할 의미와 근거가 부족한 실제 관계 후보다. 창낚시 기능과 내구도 감소 사이 인과를 확정하지 못한 14건은 별도 표현해야 한다. A 전체 조사 미해결이 14건이라는 뜻은 아니다.

구체적으로 연료·불쏘시개·마찰 점화는 대상별 분기를 묶고, 확인된 맥락 포함 관계는 명시된 역할 집합이 같을 때만 적용한다. 기능·효과는 근거를 확인한 exact 대응표로 연결한다. 노트의 보기·쓰기·페이지/제목·잠금은 복합 블록이지만 각각의 조건은 유지한다. 등록된 관계 밖의 의미를 단어 유사성이나 같은 조사 규칙만으로 합치지 않는다.

최종 집중 검사 `exit 0, 1 passed in 15.34s`는 전체 사실 보존·참조/조건 구조·대표 사례·reader를 확인했다. 모든 관계의 인간 의미 전수 검수, upstream 게임 사실 진위, KO/EN 자연스러움, 제품 UI는 검증하지 않았다. 문제 1의 규칙을 입력으로 사용하되 발견된 결함까지 무조건 정답으로 고정하지 않는다.

사용자가 재확인한 Tooltip은 최대 4줄이며, 첫째 줄은 2계층 소분류, 둘째 줄은 DVF 설명, 셋째 줄은 획득 장소, 넷째 줄은 4계층 상호작용(레시피·우클릭 행동·자유 조리)의 랜덤 표시다. 비어 있지 않은 장문에 `logical_rows=1`을 붙이는 것으로 둘째 줄의 설명 요구를 충족하지 않는다. 기존 표시 정책을 바꾸거나 Tooltip을 넓혀 표현 결함을 가리는 작업은 요구하지 않는다.

과거 실패 비교 자료는 `Iris/_docs/authority/dvf/layer3_expression/successors/r6/descriptions.json`으로 2,105 exact FullType의 KO/EN S2·expanded를 담는다. 29,202개 결합 사실과 58,404개 fact-locale 대응이 기록돼 있으나 그 수가 가독성이나 문장 의미의 정확성을 증명하지 않는다. 이전 주장의 bounded unresolved 4,223개가 남아 있고 모든 아이템 조사 완료를 주장하지 않는다.

| KO 문장 경계 누락 S2 129개 / expanded 379개 | 원문 결합 결함. 화면 렌더링만의 문제로 돌리지 않는다. |

| KO S2 고유 문장 700종 읽음, EN 고빈도 180종과 위험군 대조 | 모든 FullType의 전체 맥락이나 저빈도 영어 상세 문장을 개별 정독한 것은 아니다. |
| expanded locale당 11,594 entry | 반복/복잡/오류군을 읽었으며 모든 게임 사실 진위 재조사는 하지 않았다. |
| 과거 S2 공백 121개, expanded 공백 각 62개 | 당시 S2는 compact 비적용 110과 upstream gap 11이었다. 현재 숫자가 같아도 현재 부재 원인은 위의 입력 없음/획득 전용 구분을 따른다. |

검수 중 제안한 요약에서도 Hammer의 수리 대상/도구 의미 전환과 Notebook 조건 합침이 발견됐다. 검수자는 자연스러움을 위해 의미를 바꾸지 않아야 하며 개선 예시도 별도 근거 없이 정답으로 사용하지 않는다.

## 4. 목표

- 문제 2가 만든 2,105개와 두 언어의 compact/expanded 전체 결과를 같은 입력·규칙 기준으로 검수한다. 이미 생산된 결과는 재사용하며 단순 검수 착수를 이유로 다시 생산하지 않는다. 누락 또는 수정이 있을 때 필요한 생성·재생성을 한다.
- 전체 출력의 실제 조합 맥락을 검수해 기능 중복·조건 오적용·장문·문장 경계·직역투·층위 혼입·한영 모순을 찾아 해결한다.
- 같은 문장군은 재사용해 검토하되, 아이템별 결합 때문에 생기는 오류와 저빈도 항목을 놓치지 않는다.
- 정상 부재, 상류 근거 한계, 새 생성 실패, 미검수 영역을 구분한다.
- B/C에 같은 검수된 설명 자료와 필요한 변경/미해결 범위를 넘기며 이전 r6의 PASS를 새 결과에 승계하지 않는다.

전수 범위는 모든 아이템의 모든 게임 사실을 처음부터 조사한다는 뜻이 아니다. 다만 전체 품질 수락을 주장하려면 실제로 확인한 표면과 조합 범위를 근거 있게 설명할 수 있어야 한다. 미검수 영역을 통과로 채우지 않는다.

## 5. 대상, 책임 경계 및 범위 밖

### 포함 대상

문제 2 전체 출력과 원문 그대로 읽을 수 있는 검수 자료, 실제 문장과 의미 관계의 검수, 결함 유형/영향/원인 구분, 문제 2의 공통 문장 규칙 정정과, 실제 의미 구조 결함이 확인된 경우 문제 1 책임으로의 최소 환류 후 영향 범위 재생성·확인, 후속 공급 가능한 결과가 대상이다. 발견한 품질 결함을 분류하고 끝내지 않으며 독립적으로 해결 가능한 항목은 수락 전에 처리한다. 대표 아이템은 결함을 발견하는 수단이고 수정/수락 대상은 공통 규칙이다. 반복되는 어색함은 생성기의 배치·문법·어휘 규칙을 고쳐 해결하고, 출력 파일만 손으로 바꾸거나 FullType별 대체문 예외를 늘려 다음 생성에서 되돌아가는 수정은 하지 않는다. 같은 규칙을 쓰는 다른 아이템의 영향도 확인한다. 이는 별도 네 번째 문제나 반복 승인 절차를 추가하라는 뜻이 아니다.

사실 진위가 의심되는 항목은 기존 semantic/audit의 관련 근거를 확인하여 표현 오류인지 근거 부족인지 구분한다. 근거가 실제로 부족한 항목은 한계로 남기되 미수행 해석을 진짜 근거 한계로 위장하지 않는다. 광범위한 새 게임 조사로 확대할 필요가 있으면 영향과 별도 책임을 명시한다.

### 범위 밖

B의 Tooltip 공급·설치·4줄 조립 변경, C의 Menu UI·탐색 구현, 사용자 current 활성화·배포, 전체 미해결 주장 해소, 전체 분류 재설계, 새 품질 점수 authority·정규 validator 체계는 제외한다. 기존 표시 조건을 읽고 설명의 적합성을 확인하는 것은 가능하나 제품 UI를 바꿔 맞추지는 않는다.

### 작업 조건

Windows/PowerShell 저장소 내 기존 자료를 사용한다. 원본 r6와 기존 dirty 변경을 보존하고 문서는 docs 아래 역할 기반의 짧은 경로를 사용한다. 고정 표본 수·검수용 폴더 수·전용 웹 앱은 요구하지 않는다. 현재 `physical_fit`은 미측정이다. 실제 게임 화면을 확인할 수 없다면 물리적 폭/폰트 적합성은 미확인으로 남기고 B 인게임 완료로 주장하지 않는다. 다만 화면 측정 없이도 보이는 절차 누적·반복·긴 나열·추상 표현은 본 문제의 문장 결함으로 판단해야 하며 전부 B로 떠넘기지 않는다. 별도 폰트 측정기·layout 엔진 구축은 요구하지 않는다.

## 9. 완료 조건과 필요한 증거

| 조건 | 필요한 결과 |
|---|---|
| Q1. 전체 결과와 검수 범위 | 2,105개 KO/EN compact·expanded 8,420개 상태를 대상으로 실제 존재하는 전체 문장과 부재/실패 사유를 확인했다. 문장군 검토와 아이템별 조합 검토의 범위, 미확인을 구분한다. 부재에 문장 검수 PASS를 붙이지 않는다. |
| Q2. 의미·언어 결함의 수습 | 어색함·간결성·자연스러움·번역체와 역할/조건/대안 보존을 실제 문장에서 확인했다. 발견한 해결 가능한 결함은 공통 규칙 등 재생성 가능한 방식으로 수정하고 영향 범위의 결과를 다시 읽었다. 원문·문제점·수정안·공통 규칙 수정 여부와 같은 유형의 영향이 설명되며 대표 한 아이템의 개선이나 길이 지표만으로 통과하지 않는다. |
| Q3. 후속 소비와 한계 | B/C가 사용할 같은 설명/참조 구조와 변경 범위가 준비돼 있다. 근거 부족·정상 부재·실제 화면 미검증을 구분하고 B/C/current 완료는 별도로 남긴다. |

완료는 전체 처리 기록의 존재가 아니라 실제 원문의 품질 수락과 결함 수습이다. 전수 검수 미완료는 partial로 남기고, 근거 없는 원문을 유창하게 고쳐 정상화하지 않는다. 현재 입력에 없는 사실의 재조사와 실제 PZ 검증을 완료했다고 주장하지 않는다.

품질 기준과 수락 방식은 실제 문장·의미 보존·Tooltip 역할에서 도출하며 임의 점수/글자 수/결함 개수 quota를 고정하지 않는다. 필수 결과가 미충족이면 품질 검수 완료로 닫지 않는다. 전체 2,105개 KO/EN compact·expanded를 검수 대상으로 삼되 동일 문장/동일 조합 검토는 공유할 수 있다. 실제로 읽거나 공통 검토로 덮은 범위와 미검수 범위를 구분하며, 미검수 범위를 남긴 상태에서 전체 품질 수락으로 닫지 않는다.

검사와 읽기 자료를 공유하고, 코드 수정에 필요한 자동 검사는 계획에서 최소화해 마지막에 묶는다. 언어 검토와 수정 작업 자체를 중간 자동 테스트 금지와 혼동하지 않는다. 이미 유효한 생성 결과를 재사용하고 수정 영향이 있는 범위만 재확인한다. 저장소 전체 Run A/B + comparator, 문제 1 재수락, historical replay, 새 proof tree, 별도 언어 품질 점수 Gate나 매번 전체 corpus/전체 suite 재실행은 자동 요구하지 않는다. 실제 적용 계약의 필수 검증은 계획에서 확인하고 충돌은 숨기거나 우회하지 않는다.

## 10. 입력 전달 전 확인

새 세 문제와 기존 B/C의 책임 중복을 제거했다. 문제 1/2의 완료 입력, 2,105개 처리와 문장 존재/품질의 차이, 실제 원문 reader·상태 분포·조건 배치 연결, 기능군 단위 공통 규칙 수정 책임을 반영했다. 전체 품질 검수와 전체 게임 사실 재조사, 원문 보존과 잘못된 문장 유지, 생성 수락과 실제 제품 표시 완료를 구분했다. 미제공 로그/화면 없이도 현재 실패·목표·범위를 이해할 수 있으며 검수 수단·단계·검사 수는 설계 여지로 남겼다.
