## 확인된 문제

### 1. 철회된 지적: 표백제의 섭취 결과 누락

`Base.Bleach`, 전문 66군. KO Compact/Expanded 모두 “바닥 혈흔을 지울 수 있다. 마실 수 있다.”이며 EN도 동일한 의미다.

섭취 동작의 존재는 설명하지만, 그 동작을 이해하는 데 중요한 중독 결과를 빠뜨린다. 오염된 물과 독성 야생 식품에는 위험을 설명하는 현재 문장들과도 균형이 맞지 않는다. 사용 권고를 피하는 것과 확인된 불이익을 생략하는 것은 다르다.

근거: `scripts/items_food.txt:2859`의 Bleach는 `Poison=true`, `PoisonPower=120`을 선언한다. 설치된 B41의 `BodyDamage.JustAteFood(Food,float)` 바이트코드에서도 양의 PoisonPower를 섭취량에 곱하고 특성을 반영해 PoisonLevel과 통증에 더하는 경로를 확인했다. 현실의 표백제 상식으로 판단한 것이 아니다.

수정 방향: 섭취를 남긴다면 중독 결과와 연결해 설명한다. 구체적인 치사량이나 반드시 죽는다는 결과까지 이 확인으로 주장하지 않는다.

### 2. 철회된 지적: 수박의 가공 용도가 양쪽 설명에서 누락

`Base.Watermelon`, 360군. 네 설명 모두 “덫의 미끼로 쓸 수 있다.”에 해당하는 내용만 있다.

근거: `scripts/recipes.txt:304`의 Slice Watermelon은 수박을 소비하고 적합한 절단 도구를 보존하여 WatermelonSliced를 만든다. 같은 파일 317행의 Smash Watermelon은 수박을 소비하고 망치·통나무 등의 도구를 보존하여 WatermelonSmashed를 만든다. 현재 망치·통나무·판자·대형 망치의 Expanded에는 수박을 쪼개는 용도가 실제로 출력된다.

이는 원본 근거가 없는 공백이 아니다. 처리 도구에는 해당 작업을 설명하면서 처리 대상인 수박에는 결과를 얻는 용도를 설명하지 않는 비대칭이다. 제작 재료를 무조건 주요 용도로 삼아서는 안 되지만, 음식의 손질은 처리 대상 자체를 이해하는 데 유용하다.

수정 방향: 손질하거나 쪼개서 조각을 얻는 역할을 수박 설명에 반영한다. 원형 수박을 바로 먹을 수 있다고 바꾸는 것은 별개의 주장이다.

다음은 문장만으로 충분히 이해하기 어렵다고 평가하지만, 이번에 해당 동작 전체를 재증명하지 않았으므로 곧바로 새 설명을 넣을 근거로 삼지 않는다.

- `Base.NoiseTrap`·`Base.SmokeBomb`, 367·458군: 개조와 투척 공격만 설명해 소음·연막의 구체적 기능을 설명하지 않는다. 이름으로 효과를 추정해 보충하지 말고 실제 효과 경로를 조사해야 한다.
- `Radio.WalkieTalkie*`·`Radio.HamRadio*`, 512–513군: 방송 청취만 설명한다. 송신·통신 기능의 적용 조건을 조사할 가치가 있다.

## 잘된 부분

- 망치류: 불필요한 도구 분류어 없이 작업 목적을 직접 말한다. Compact가 개요이고 Expanded에 독립 용도가 남아 있다.
- 물: 보관·운반·이동, 농사, 세척, 소화, 음용을 구별하고 오염 위험을 음용에 연결한다. Compact에 Expanded 문장을 전부 복사하지 않는다.
- 가구: 근거가 연결된 항목은 수납·취침·조리·조명 등 기능을 앞에 두고 이동과 재료 회수를 별도 문장으로 제공한다. 일부 항목의 문장 순서는 더 다듬을 수 있지만 역할 분리는 명확하다.
- 수리 재료: Compact는 수리 범주를 요약하고 Expanded는 실제 대상 목록을 보존한다. 목록이 길다는 이유만으로 내용을 삭제할 필요는 없다.
- 페인트: “일부 문/의자/상자/탁자”의 범위를 보존한다. 호환 부품·덫·오염된 물 등에서도 조건을 의미 있게 설명하는 사례가 많다.
- 추천, 효율 순위, 플레이 선택의 강요가 전반적으로 보이지 않는다. 단순한 항목은 C/E가 같아도 결함이 아니다.
