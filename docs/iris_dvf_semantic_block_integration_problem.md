# 문제 1 — 멀티 프로필 조사 결과의 의미 블록 통합 규칙

## 1. 문제명과 입력 기준

- 문제 ID: DVF-COMPOSITION-1
- 입력 버전 / 기준일: v1 / 2026-09-10
- 대상: Iris DVF의 채택 사실에서 사용자 설명용 의미 블록을 구성하는 책임
- 기준 상태: 기존 문제 A는 멀티 프로필 기반 조사·사실·설명 데이터 r6를 생산했다. 이후 실제 Tooltip과 설명 검수에서 품질 실패가 확인돼 A의 설명 품질 완료 판단을 유지할 수 없게 됐다. 이 문서는 과거 생산·테스트 기록을 지우지 않고 부족한 의미 통합 규칙을 문제화한다.

기존 A/B/C와 구분하기 위해 새 문제 1~3을 DVF-COMPOSITION으로 식별한다. 두 로드맵 작성자에게 동일 버전과 공통 문서를 전달한다. 원본 코드·r6·검수 보고서를 웹 작성자가 읽을 수 있다고 가정하지 않고 필요한 내용을 아래에 요약한다.

## 2. 문제 정의

### 현재 상태와 기대 상태의 차이

하나의 아이템이 여러 Profile에서 조사되고 기능·역할·대상·조건·결과를 가진 사실이 만들어졌지만, 이들을 사용자에게 설명할 때 무엇을 같은 의미로 통합하고 무엇을 독립 의미로 보존할지에 대한 충분한 공통 규칙은 확보되지 않았다. 일부 문장 템플릿과 연료/불쏘시개 묶음은 존재하므로 “아무 규칙도 없다”는 코드 부재 주장은 아니다. 문제는 전체 조합을 일관되게 결정할 의미 통합 기준의 부족이다.

현재 판자는 `목공 작업`, `목공 건축`, `건축 작업`과 유사한 조건을 별도 표현으로 반복한다. 반대로 이름만 비슷하다고 묶으면 서로 다른 역할과 조건을 잃을 수 있다. 조사 경로의 수나 이름이 사용자 설명 블록을 결정해서는 안 된다.

필요한 결과는 **채택 사실의 의미 관계를 근거로 중복·포함 관계·독립 용도와 조건의 적용 범위를 구분하는 공통 규칙**이다. 생성된 나쁜 문장의 빈도를 통계적으로 묶는 것만으로 규칙을 도출하지 않는다.

### 영향과 필요성

의미 통합이 없으면 후속 생성기는 사실 문장을 계속 이어 붙이거나 개별 아이템 예외를 늘리게 된다. 반대로 길이만 줄이면 수리 대상이 수리 도구로 바뀌는 등의 의미 손실이 생긴다. 설명 조합기를 구현하기 전에 이 판단 기준이 필요하다.

## 3. 필요한 배경과 현재 상태

| 요소 | 역할과 경계 |
|---|---|
| Profile | 조사를 위한 관점. 하나의 아이템에 여러 개가 적용될 수 있으며 UI 섹션이나 대표 역할이 아니다. |
| 채택 사실 | 기능·역할·맥락·조건·결과와 근거 참조를 가진 조사 결과. 사실마다 모든 필드가 완비됐다고 가정하지 않는다. |
| 의미 블록 | 사용자에게 설명할 하나의 의미와 그 적용 관계를 담는 개념 단위. 새 저장 파일이나 고정 schema를 미리 요구하는 용어가 아니다. |
| compact / expanded | 같은 의미를 Tooltip 둘째 줄의 짧은 설명과 Menu의 상세 설명으로 각각 표현한 결과. 문장 생성은 문제 2다. |
| audit / residual | 이전 주장 판정, 내부 조사 한계와 남은 불확실성. 전부 공개 문장으로 출력할 대상이 아니다. |

Iris의 1계층은 기본 정보, 2계층은 분류 의미, DVF가 맡는 3계층은 아이템별 기능·맥락 설명, 4계층은 정확한 제작법·행동·대상 관계, 5계층은 내부 데이터다. DVF는 다른 계층의 주인이 아니다.

사용자가 재확인한 Tooltip은 최대 4줄이며, 첫째 줄은 2계층 소분류, 둘째 줄은 DVF 설명, 셋째 줄은 획득 장소, 넷째 줄은 4계층 상호작용(레시피·우클릭 행동·자유 조리)의 랜덤 표시다. 비어 있지 않은 장문에 `logical_rows=1`을 붙이는 것으로 둘째 줄의 설명 요구를 충족하지 않는다. 기존 표시 정책을 바꾸거나 Tooltip을 넓혀 표현 결함을 가리는 작업은 요구하지 않는다.

현재 기준 자료는 `Iris/_docs/authority/dvf/layer3_expression/successors/r6/`의 descriptions·semantic·acquisition·audit다. 2,105개 exact FullType, 결합 사실 29,202개, KO/EN 사실 대응 58,404개를 기록한다. 이전 claim 중 보존 3,522개, 책임상 제거 2,233개, bounded unresolved 4,223개가 있으며 모든 아이템의 조사가 완료된 것은 아니다. 이 수치는 새 규칙의 목표 quota나 사실 진위 재검증 결과가 아니다.

가독성 검수에서는 expanded 블록 간 동일 문장이 614개 아이템에서 반복됐고, KO S2의 1,553개가 3문장 이상이었다. 문장 수는 부담 지표이며 개별 의미 오류 확정 수는 아니다. KO 고유 S2 문장 700종은 읽었지만 모든 expanded/영어 문장·게임 사실을 전수 재검증하지는 않았다.

관계 보존의 실제 반례가 있다. Hammer의 “수리할 수 있는 물품”을 “수리에 사용할 수 있다”로 요약하면 대상/도구 역할이 바뀐다. Notebook에서 작성에 필요한 필기구 조건을 잠금 기능까지 확대하면 조건의 적용 대상이 바뀐다. 통합 규칙은 이런 변화도 막아야 한다.

## 4. 목표

- 같은 의미의 중복 발견, 상위·하위 관계, 독립 용도, 함께 표현할 수 없는 대안/조건을 구분할 수 있다.
- 기능과 해당 대상·조건·결과를 연결하고, 전역 조건과 특정 용도의 조건을 혼동하지 않는다.
- 여러 Profile의 출처를 보존하면서 사용자 의미는 불필요하게 중복하지 않는다.
- 현재 사실 구조로 결정할 수 없는 관계와 표현 규칙만으로 해결 가능한 관계를 구분한다.
- 후속 생성기가 원문 문장 유사도나 Profile 이름을 추측하지 않고 같은 의미 구성을 재사용할 수 있다.

규칙의 표현 형식, 자료구조, 구체적 분류 체계와 저장 방식은 로드맵에서 정한다. 특정 아이템 이름별 수작업 목록을 일반 규칙의 대체물로 삼지 않는다.

## 5. 대상, 책임 경계 및 범위 밖

### 포함 대상

멀티 프로필 사실의 중복/독립성, 역할·조건·결과 관계, 공통 조건의 적용 범위, 근거 추적과 의미 블록의 구성 기준이 대상이다. 기존 구조가 부족하면 확인된 부족을 해소하는 최소 관계 정보 보완도 포함한다. 단순한 문장 재배열로 해결할 수 없는 사실 구조 결함을 표현기로 떠넘기지 않는다.

### 범위 밖

한국어·영어 최종 문장 생성과 생성기 구현 전체(문제 2), 전체 설명 재생성·품질 수락(문제 3), 기존 B의 Tooltip 연결 및 C의 Menu UI, 남은 미해결 주장 전수 조사, 2계층 분류 재설계, 새 게임 효과 추론은 제외한다. 이번 작업에서 의미 구분을 입증할 구체 예시를 만드는 것은 허용되지만 예시만으로 전체 적용 완료라고 하지 않는다.

### 작업 조건

Windows/PowerShell 저장소와 채택 자료가 있다. 기존 dirty 변경과 r6 원본은 보존한다. 설명 문서는 docs 아래에 둔다. 이 문제 문서는 외부 경로 접근, 새 checkout, 커밋·배포·게임 설치를 승인하지 않는다.

## 6. 선행 조건과 의존 관계

| 입력/후속 | 현재 상태와 의미 |
|---|---|
| A의 멀티 프로필 사실 | 확보된 출발 자료. 모든 unresolved 해소를 기다리지 않는다. |
| 문제 2 설명 조합기 | 이 문제의 의미 구분과 조건 관계를 소비한다. 구체 schema 협의는 병행할 수 있다. |
| 문제 3 전체 품질 검수 | 실제 출력에서 규칙이 누락한 관계를 찾아 필요한 책임으로 환류한다. |
| 기존 B/C | 공급/표시 기반은 보존한다. 새 설명 검수 전 최종 적합성 완료로 취급하지 않는다. |

입력 구조의 부족이 광범위하다고 확인되면 부족의 범위와 후속 영향을 명시한다. 처음부터 별도 전수 데이터 개편 문제를 추가하거나 네 번째 과제를 가정하지 않는다.

## 7. 필수 불변식과 금지 사항

| 조건 | 근거와 영향 |
|---|---|
| primary_use·대표 용도 하나로 축약하지 않음 | 사용자 확정 요구. 의미를 묶는 행위가 다른 독립 용도를 삭제하는 정책이 되면 안 된다. |
| 조사 Profile과 사용자 의미 구분 | 멀티 프로필 구조의 목적. 같은 기능을 여러 경로에서 찾았다고 여러 용도로 출력하지 않는다. |
| 역할·조건·대안·결과의 적용 범위 보존 | 근거 기반 설명. 이름 유사성/공통 단어만으로 합치거나 다른 Type의 조건을 붙이지 않는다. |
| 상세/공개 의미와 내부 조사 기록 구분 | 모든 audit 행을 사용자 블록으로 승격하지 않는다. 미해결을 전역 사용 불가로 단정하지 않는다. |
| 불확실성을 추측으로 채우지 않음 | 충분한 근거가 없으면 판단 한계를 유지하되, 기존 근거로 할 수 있는 해석을 미수행 상태로 방치하지 않는다. |

## 8. 참고 아이디어와 불확실성

| 질문 | 영향과 알려진 단서 |
|---|---|
| 현재 사실의 어떤 관계 정보가 통합에 충분한가 | typed payload와 근거는 있지만 사용자 의미의 동일성·포함 관계가 모두 명시됐는지는 미확인이다. |
| 비슷한 건축/목공 맥락이 실제로 얼마나 겹치는가 | 판자의 반복 표현은 확인됐지만 명칭만으로 전부 같은 의미라고 할 수 없다. |
| 공통 행위의 어떤 조건이 해당 기능을 구별하는가 | 세척·연료 사실의 빈도는 높지만 그 사실 자체의 오류/삭제 사유는 아니다. |
| 충돌하거나 관계를 확정할 수 없는 사실을 어떻게 후속에 전달할 것인가 | 불확실성을 숨기지 않으며 최종 표현 책임과 조사 책임을 구분해야 한다. |

구체적 통합 규칙은 조사 결과로 제시해야 한다. 이 문서는 특정 ontology·그래프·필드 수를 필수로 정하지 않는다.

## 9. 완료 조건과 필요한 증거

| 조건 | 필요한 결과 |
|---|---|
| M1. 재사용 가능한 의미 판단 | 중복·독립·포함/대안 및 조건 귀속을 실제 사실 관계로 설명할 수 있고, 같은 유형에 공통 적용할 수 있다. 규칙 목록 작성만으로 충족하지 않는다. |
| M2. 보존과 경계 확인 | 복합 용도·중복 조사·다른 조건·역할 전환 위험·정보 부족 사례에서 어떤 의미가 통합/유지/판단 보류되는지 근거와 함께 보인다. 표본 수와 방식은 계획에서 정한다. |
| M3. 생성기로 넘길 수 있는 결과 | 문제 2가 소비할 의미 구조/규칙과 미해결 관계의 처리 경계가 명확하다. 현재 자료에 필요한 최소 보완과 미완료 범위가 드러난다. |

세 조건은 별도 Gate 세 개를 요구하지 않는다. 같은 사실·예시를 공유하고 기존 검사를 재사용한다. 새 validator/봉인/전수 provenance 재검사나 A의 장시간 검사를 자동으로 추가하지 않는다. 완료는 의미 통합 규칙의 확보이며 문장 품질·제품 표시 완료가 아니다.

## 10. 입력 전달 전 확인

현재 실패와 원하는 의미 구조, Profile과 사용자 의미, 중복 제거와 의미 삭제를 구분했다. 원본 설명의 재그룹화만으로 의미 규칙을 도출할 수 있다고 가정하지 않았다. 구체 schema·단계·검사 수는 고정하지 않고 사실 기반의 완료 결과를 명시했다.
