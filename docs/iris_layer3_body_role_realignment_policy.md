# Iris Layer 3 body-role realignment policy

Status: owner-ratified implementation policy, 2026-08-21.

Layer 3 is an optional explanatory layer. It may present an overview when confirmed description-eligible material exists, but it does not manufacture a description from identity, classification, acquisition, Layer 4 richness, page disposition, or rendered-text interpretation. Insufficient evidence remains silent.

The canonical item denominator is the exact case-sensitive `FullType` set in `Iris/input/items_itemscript.json`. The existing-body denominator is the non-empty `text_ko` set in the generation selected at execution time by `IrisLayer3DataCurrent.lua`. Planning counts and generation IDs are observations, not constants.

Every existing body receives one of `keep`, `reduce`, `revise`, `hide`, or `review_hold`. Every canonical item independently receives one of `description_ready`, `acquisition_only`, `omission_allowed`, `insufficient_material`, or `review_required`. Only confirmed `role`, `target`, `action`, `result`, `consumption_or_retention`, `condition`, or `restriction` material opens description readiness. Identity, classification, and acquisition alone do not.

Source facts are admitted only through the exact mapping contract. Scalar mapping is keyed by source slot and provenance; `cluster_summary` additionally requires a matching adopted Layer 3 decision lineage. Free-form prose and rendered `text_ko` are never parsed to infer fact kind. New source/provenance or structured-lineage combinations fail closed until an additive policy successor ratifies them.

Canonical staging material separates `core_description` and `acquisition_information`. Acquisition facts remain source-bound and are conserved independently of current public expression. Menu compatibility uses the four-case projection in the adopted plan. The selected public branch is `preserve_current_publicity`: only acquisition facts whose predecessor source-to-render trace confirms current expression are included in flat Menu text. Acquisition-only output remains acquisition material and is never reclassified as a core description. Tooltip work stops at role-labeled input readiness.

The transformation registry is closed to the five operations ratified in `transformation_rules.json`. Exact duplicate detection is an audit signal. It blocks only a registered bad duplicate, an exact text collision with different semantic consumed-fact sets, or another explicit eligibility defect. High frequency alone is advisory. Human exceptions cannot add facts and become stale when any bound input identity changes.

The preserved Item-Page Information Sufficiency result is one-off, read-only evidence with no authority effect and no regular-gate role. When its exact snapshot is current, only its per-item Layer 3 axes may support readiness prerequisites. Top-level page disposition, Layer 4 axes, and gap inventory never determine body disposition, core eligibility, or Problem 5A membership. Drift makes the one-off evidence stale; it does not authorize equivalence waivers or evaluator restoration.

Default completion is staging-only. The current generation, runtime payload, package projection, Menu public text, and Tooltip UI remain unchanged unless the separately authorized official seven-input complete-generation path is executed and all installation-specific gates pass. Stateful Artifact Registry lifecycle, RTC, Publish, release, Workshop, and deployment claims are outside this policy.
