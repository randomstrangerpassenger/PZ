# Iris 메뉴의 표시·조작 안정성 부족

## 1. 문제명과 입력 기준

- **문제명:** Iris 메뉴에서 제공된 정보를 읽고, 입력을 이어가고, 관련 항목으로 이동하는 동작이 충분한 안정성과 일관성을 제공하지 못하는 문제
- **입력 문서 버전 / 기준일:** v1 / 2026-08-31
- **대상 영역:** Iris 메뉴의 Browser, 상세 패널, 상호작용 목록과 기존 제작창 연결. 같은 표시 경로 또는 변경 영향을 공유하는 Wiki 패널을 포함한다.
- **기준 상태:** 작업공간 HEAD `f8da88748b09c67f0adb89daa6b28f543500bc48`에서 확인한 메뉴 구현과 아래에 설명한 독립 Lua 모의 실행. 이 식별자는 소스 관찰 기준이며, 사용자가 실제 실행 중인 설치본·게임·모드 환경과의 일치를 뜻하지 않는다.
- **사용자 범위 결정:** 설명 품질은 별도로 개선할 예정이므로 이번 문제에서 제외한다. 한국어 아이템 검색 품질은 별도 문제로 다루며, 첫 사용 안내와 배포 기본사항도 제외한다.

공통 문서에 정의된 Iris의 역할과 구조를 전제로 한다. 이 문서는 그 문서들만으로 알 수 없는 메뉴 관련 관찰, 미충족 요구와 이번 작업의 경계를 제공한다. 제품의 구현 완료, 과거 기능 검증과 이번 메뉴 문제의 해소 여부는 구분한다.

## 2. 문제 정의

### 현재 상태와 기대 상태의 차이

현재 메뉴에는 아이템 탐색, 상세 정보 표시, 상호작용 목록의 접기·검색, 제작창 이동과 요구조건 표시가 구현되어 있다. 그러나 구현을 조사한 결과, 입력 중인 검색창이 결과 갱신 과정에서 교체되는 경로와 패널 폭을 고려하지 않고 긴 텍스트·버튼을 배치하는 경로가 확인됐다. 제작창 연결과 요구조건의 표시·갱신에는 구현만으로 사용자 관점의 정확성을 확정할 수 없는 부분도 있다.

기대 상태는 사용자가 **이미 제공된 정보를 읽고, 시작한 입력을 계속하고, 선택한 레시피로 이동하며, 표시된 조건의 상태를 오해 없이 확인할 수 있는 것**이다. 정보의 내용이 더 풍부해지거나 문장이 더 좋아지는 것은 이번 문제의 목표가 아니다.

기대의 근거는 이 대화에서 정리한 메뉴 안정성 개선 방향과 사용자의 해당 문제 문서 작성 요청이다. 구체적인 화면 구성, 상태 복원 범위, 지원 해상도·글꼴 조합, 응답 시간의 수치 기준은 확정되지 않았다. 앞서 제안된 모든 편의 기능이 필수 요구로 승인된 것은 아니다.

### 영향과 필요성

영향을 받는 대상은 Iris 메뉴에서 상세 정보를 읽고 상호작용을 찾는 사용자다. 입력이 끊기거나 조작 대상이 화면 밖으로 밀리면, 정보가 존재해도 접근하기 어렵다. 요구조건의 표시가 실제 확인 상태와 맞지 않거나 레시피 연결이 기대한 대상을 보여주지 않으면 사용자는 다시 탐색해야 할 수 있다.

현재 확인된 것은 소스상의 동작과 제한된 모의 실행 결과다. 실제 게임에서 발생하는 빈도, 재입력 횟수, 작업 지연과 환경별 심각도는 측정되지 않았다. 이 문제를 설명 품질이나 검색 알고리즘 개선에 묶어 두면, 내용이 개선되어도 정보를 읽고 조작하는 경로의 결함이 남을 수 있으므로 별도로 다룬다.

### 독립 모의 실행에서 확인한 내용

2026-08-31 문서 작성 시점에 현재 Browser 상세 처리와 상호작용 렌더링 코드를 독립 Lua로 실행했다. 게임의 위젯·글꼴 측정·아이템 모델·데이터 조회는 모의 객체로 대체하고, 구조화된 레시피 9개를 입력했다.

검색창에 포커스를 둔 뒤 `R` 한 글자의 입력 변경을 호출한 결과는 다음과 같다.

- 생성된 검색창은 1개에서 2개가 됐다.
- 기존 검색창은 상세 패널에서 제거됐다.
- 새 검색창의 문자열은 `R`로 유지됐다.
- 모의 위젯에서 새 검색창으로 포커스를 복원하는 호출은 없었다.
- 해당 관찰을 확인한 독립 실행은 종료 코드 `0`이었다.

이는 **현재 코드가 입력 위젯을 교체하며 명시적인 포커스 복원을 하지 않는다는 증거**다. PZ가 실제로 입력을 어디에 전달하는지, 한글 조합이 끊기는지, 글자가 유실되는지를 확인한 인게임 증거는 아니다. 글꼴 폭도 모의 값이므로 이 실행으로 화면 적합성이나 성능을 판단하지 않는다. 이 모의 관찰을 새 정규 validator나 별도 검증 authority로 만들라는 요구는 없다.

관찰한 코드의 위치는 후속 계획 작성자가 다시 확인할 수 있으나, 로드맵 작성에 필요한 동작과 한계는 위 본문에 포함했다. 웹의 로드맵 작성자에게 저장소 또는 미제공 로그의 재감사를 요구하지 않는다.

## 4. 목표

### 반드시 달성해야 하는 결과

- 상호작용 목록에서 입력을 이어가고 수정·삭제하는 동안, 결과 갱신 때문에 사용자가 입력 대상을 불필요하게 다시 선택하지 않아도 된다.
- 수용 범위로 정한 화면·글꼴·언어 조건에서 이미 제공된 메뉴 텍스트를 끝까지 읽고 관련 버튼을 조작할 수 있다.
- 접기·펼치기·스크롤·아이템 전환 후 화면에 표시된 내용과 사용자의 조작 대상이 일치한다.
- 기존에 제공하는 레시피 연결은 의도한 대상을 찾을 수 있는 제작창 상태로 이어지며, 연결할 수 없는 경우 이를 성공한 이동으로 오인하게 하지 않는다.
- 기존 요구조건의 의미와 확인 가능 범위를 유지하면서, 명칭과 상태가 읽을 수 있고 정한 갱신 시점에 맞게 표시된다. 알 수 없는 조건은 확인된 조건과 구분된다.
- 메뉴 수정이 아이템 식별, 다른 언어·generation의 상태 격리, 기존 제작법·우클릭 정보의 구분을 훼손하지 않는다.

확인되지 않은 레시피·조건 표시 문제는 먼저 실제 차이를 판정해야 한다. 해당 경로가 이미 목표를 충족한다면 불필요한 코드 변경은 완료 조건이 아니다. 구체적인 환경 범위, 상태 갱신 기준과 응답성 수용 기준은 로드맵에서 정하며, 이 문서는 임의의 수치를 고정하지 않는다.

### 선택적으로 달성할 수 있는 개선

메뉴 재열기 시 선택·스크롤·탐색 맥락 복원, 방문 항목으로 돌아가는 동선은 선택 개선이다. 포함 여부를 별도로 정하며, 미구현을 필수 목표의 실패로 취급하지 않는다. 채택하더라도 특정 아이템을 지정해 여는 동작이나 언어·generation 전환의 상태 규칙을 침해해서는 안 된다.

## 5. 대상, 책임 경계 및 범위 밖

### 포함 대상

- 기존 Iris 메뉴에서 텍스트와 조건을 읽고, 상호작용 목록에 입력하고, 항목을 선택·전환하고, 관련 제작창으로 이동하는 흐름.
- 그 흐름의 위젯 수명, 포커스·커서, 배치, 행 높이, 스크롤, 표시 상태와 갱신 관계.
- KO/EN 및 실제 명칭·내용 길이가 메뉴 표시와 조작에 미치는 영향. 구체적인 환경 조합과 확인 대상은 미정이다.
- 기존 요구조건·레시피 연결 데이터가 사용자에게 표시되는 과정의 문제. 이미 확정된 조건이나 연결의 의미를 새로 만드는 작업은 포함하지 않는다.
- 같은 표시 경로 또는 수정 영향을 공유하는 기존 Wiki 패널의 회귀 여부. 모든 메뉴 화면의 전면 재설계를 뜻하지 않는다.

주된 변경 영역은 Iris의 메뉴 presentation과 UI 상태 관리다. 다만 입력이나 제작창 동작에서 나타난 증상의 원인이 반드시 Iris 내부에 있다고 가정하지 않는다. 엔진·외부 UI 변경·데이터 결손의 영향을 구분하고, 소유 범위를 넘는 수정은 자동으로 승인된 작업으로 취급하지 않는다.

### 별도 한국어 아이템 검색 문제와의 경계

별도 문제는 전체 아이템 검색과 목록 내 아이템 검색의 검색 대상, 입력 정규화, 일치 판단, 결과 순위·식별과 언어·generation별 검색 상태를 다룬다. 이번 문제는 그 알고리즘이나 검색 의미를 바꾸지 않는다.

현재 관찰된 포커스 문제는 **선택된 아이템의 상호작용 검색창**에 관한 것이다. 이번 작업은 이 입력창의 조작 연속성과 입력·결과의 연결을 다루며, 이를 이유로 상호작용 검색의 새 문법·매칭·순위 체계를 필수로 도입하지 않는다.

아이템 검색창·결과 목록과 공통 UI를 수정해야 할 경우, 이번 문제는 배치·표시·위젯 동작을 담당하고 검색어 해석과 결과 집합·순위는 별도 문제의 규칙을 따른다. 같은 파일을 사용한다는 이유로 두 문제의 요구를 서로 흡수하지 않는다.

### 범위 밖

- **설명 품질 전반:** 잘못된 설명의 교정, 문장 자연스러움, KO/EN 설명의 의미·번역 품질, 설명량과 상세 정보 충분성, 새 용도·조건·사실의 추가. 사용자가 별도로 개선할 예정이다.
- DVF의 설명 생산·조합 규칙, 정보 내용의 채택, Tooltip S2 및 Alt 툴팁 시스템 개선. 과거 DVF·툴팁 완료나 관찰 범위를 이번 문제의 잔여 의무로 다시 열지 않는다.
- 별도 문제로 정의한 한국어 아이템 검색 품질 개선.
- 첫 사용 안내, 설치·업데이트·제거 안내, 배포 문서·패키징·게시 및 출시 준비. 이번 문제의 완료 조건이나 잔여 과제로 남기지 않는다.
- 신규 메뉴 체계, 모든 외부 모드·번역팩·멀티플레이 환경의 보편적 호환성 보증, 근거 없는 광범위 성능 최적화.

**이미 제공된 설명을 읽을 수 있도록 표시를 보완하는 것은 포함되지만, 그 설명의 내용을 더 정확하거나 풍부하게 만드는 것은 제외한다.** UI 조작 명칭이나 기존 조건의 식별자를 읽을 수 있는 이름으로 연결하는 작업과 설명 본문의 번역·품질 개선도 구분한다. 표시 문제를 해결하기 위해 원문을 임의로 축약하거나 바꿔서는 안 된다.

목표 달성에 필요한 중간 작업은 위 책임 경계 안에서 도출할 수 있다. 본문에 열거되지 않았다는 이유만으로 범위 밖이 되는 것은 아니다.

### 작업 조건

현재 근거는 저장소 소스와 독립 Lua 관찰이다. 실제 PZ 버전, 활성 모드, 글꼴·해상도와 입력 환경은 이번 문제에 대해 확인되지 않았다. 게임에서의 관찰은 메뉴 변경 범위에 한정하며, 배포·게시나 기존 툴팁 검증을 재개하는 것과 구분한다. 시간·자원 제한이나 새 테스트 도구·산출물 형식은 별도로 확정되지 않았다.

## 6. 선행 조건과 의존 관계

| 필요한 상태 또는 입력 | 현재 충족 여부와 판정 기준 | 필요한 시점 | 미충족 시 영향 |
|---|---|---|---|
| 기존 아이템·상호작용·조건의 데이터와 표시 경로 | 현재 메뉴에 연결된 구현이 존재한다. 모든 항목과 상태의 동작을 검증한 것은 아니다. | 메뉴 분석·구현 및 동작 확인 | 결손을 표시 문제와 구분해야 하며, 필요한 사실을 UI에서 만들어 채울 수 없다. |
| 별도 아이템 검색 작업과의 접점 | 문제 범위는 구분되어 있다. 공통 파일·이벤트·상태의 구체적인 수정 책임은 미정이다. | 공통 부분 수정 및 통합 전 | 검색 결과의 의미와 UI 조작 변경이 섞이거나 서로 덮어쓸 수 있다. |
| 실제 게임에서 확인할 환경과 동작 범위 | 미정. 게임·언어·입력·글꼴·화면 조건 등 결과 해석에 필요한 범위를 정해야 한다. | 실사용 완료 판정 전 | 소스·모의 실행 범위의 판단은 가능하지만 실제 사용자 동작까지 완료로 주장할 수 없다. |

메뉴의 입력·배치 개선은 설명 품질 후속 작업의 완료를 기다릴 필요가 없다. 현재 제공된 내용을 소비하되, 설명 길이가 달라질 수 있다는 점은 표시 경로의 조건이다. 특정 미완성 설명이나 신규 데이터 필드를 선행 완료로 가정하지 않는다.

별도 아이템 검색 작업과 병렬 수행할 수 있는 범위가 있으나, 공통 UI·상태를 바꾸면 합쳐진 결과의 확인이 필요하다. 이는 의존 관계이며 작업 트리 구성, 병합 순서, 단계 수나 별도 통합 산출물을 고정하는 요구는 아니다.

## 9. 완료 조건과 필요한 증거

| 완료 조건 | 관찰 또는 검증 대상 | 필요한 결과 | 알려진 한계 |
|---|---|---|---|
| C1. 상호작용 검색 입력의 연속성 | 정한 입력 환경에서 입력·조합·확정·삭제와 결과 갱신 | 입력 도중 결과가 갱신되어도 조작 대상·문자열·커서가 의도에 맞게 유지되고 불필요한 재선택이 필요하지 않음 | 현재는 위젯 교체와 포커스 복원 부재를 모의 실행으로만 확인 |
| C2. 기존 정보와 조작 대상에 대한 접근성 | 정한 언어·글꼴·화면 조건의 텍스트, 버튼, 접기·스크롤 | 원문 의미를 바꾸지 않고 정보를 끝까지 읽을 수 있으며 필요한 버튼과 마지막 항목에 접근할 수 있음 | 현재 텍스트·환경 조합별 실제 적합성 증거 없음 |
| C3. 레시피 연결의 정확성 | 제공된 연결과 실제 제작창의 결과 상태 | 사용자가 지정한 레시피에 도달할 수 있고, 연결할 수 없는 상태를 성공한 이동으로 오인하지 않음 | 현재 연결 구현은 있으나 실제 게임의 결과는 미관찰 |
| C4. 요구조건 표시의 일관성 | 기존 조건, 표시 명칭, 확인 상태와 정한 갱신 시점 | 기존 의미를 유지하며 읽을 수 있는 명칭과 유효한 확인 상태를 표시하고, 알 수 없음을 단정으로 바꾸지 않음 | 적용 항목·실사용 상태 변화에 대한 증거 부족 |
| C5. 상태·식별과 인접 기능 보존 | 아이템·언어·generation 전환, 공통 UI, 변경 영향을 받는 기존 메뉴 경로 | 다른 대상의 상태 혼입이나 식별 손실이 없고, 별도 아이템 검색의 의미·결과를 이번 작업이 임의 변경하지 않음 | 병렬 변경을 합친 실제 상태는 아직 없음 |
| C6. 실제 메뉴 사용에서의 수용 가능성 | 명시된 PZ 환경과 이번 메뉴 동작 범위 | 위 목표가 실제 입력·표시·이동에서도 성립하고 정한 응답성 기준을 충족함 | 현재 모의 관찰만으로 게임 입력·화면·성능을 보장할 수 없음 |

선택 개선을 채택하면 그 결과 기준을 별도로 명시한다. 채택하지 않은 상태 복원·뒤로 가기를 위 조건의 실패로 세지 않는다. 발견한 경로가 기존 구현으로 조건을 충족한다면 그 확인 결과로 판단할 수 있으며, 모든 관찰 항목에 코드 변경을 요구하지 않는다.

검증 방법, 대상 환경과 표본, 필요한 산출물은 기존 적용 계약 안에서 로드맵이 설계한다. 이 문제 문서는 별도 반복 실행·비교기·finalizer·봉인 절차를 추가하지 않는다. 과거 DVF·툴팁 또는 다른 소스 상태의 검사 성공을 이번 메뉴 변경의 결과로 승계하지 않는다.

완료 주장은 실제로 확인한 메뉴 동작과 환경에 한정한다. 설명 품질 개선, 한국어 아이템 검색 품질 개선, 모든 모드 호환성, 배포·출시 준비 완료를 뜻하지 않는다. 문제 문서 작성이나 후속 계획 검토의 PASS도 제품 문제의 해소 증거가 아니다.

## 10. 로드맵 작성자에게 요구하는 응답

`Philosophy.md`를 가장 먼저 읽고, `DECISIONS.md`, `ARCHITECTURE.md`, `ROADMAP.md`를 작성 전에 읽는다. `ROADMAP_TEMPLATE.md`와 `EXECUTION_CONTRACT.md`의 적용 범위를 확인하고, 나머지 제공된 공통 문서는 문제와 관련된 부분을 활용한다.

공통 문서와 이 문제를 바탕으로, 해결에 필요한 사항을 독립적으로 판단하여 `ROADMAP_TEMPLATE.md`의 양식에 따라 상세한 로드맵을 작성하라. 이 문제 문서는 별도의 로드맵 양식이나 추가 필수 체크리스트를 부과하지 않는다.

확정 목표와 필수 제약 안에서 접근 방식, 작업 분해, 단계 구성, 의존성 처리, 산출물과 검증 전략을 자유롭게 설계할 수 있다. 문제 문서의 나열 순서를 실행 순서로 따르거나, 각 항목을 하나의 단계로 옮길 필요는 없다. 참고 아이디어를 사용하지 않아도 된다.

상세함은 항목 수나 단계 수가 아니라, 선택한 접근이 문제를 어떻게 해결하고 완료 조건에 도달하는지 후속 계획 작성자가 이해할 수 있는 정도를 뜻한다. 문제 해결에 필요한 중간 작업을 스스로 도출하되, 제공되지 않은 파일·API·환경·완료 상태를 사실처럼 만들지 않는다. 저장소 확인이 필요한 구현 세부는 Codex의 계획 단계에서 구체화할 수 있다.

제공된 사실은 직접 검증했다고 주장하지 않는다. 문제의 가설이나 설명을 비판적으로 검토할 수 있으며, 공통 문서와의 충돌은 선언된 권위 관계와 범위에 따라 다룬다. 기존 확정 결정을 바꾸는 제안은 현재 허용된 실행 방향과 구분한다.
